# Chat Graph 对话总结功能 PRD

> 版本：V0.1  
> 产品：Chat Graph 浏览器插件  
> 功能名称：对话总结 / Conversation Review  
> 文档状态：可进入设计与开发

---

## 1. 背景

用户与 GPT 进行较长对话时，经常会出现以下问题：

- 讨论了很多内容，但结束后无法快速说清楚自己到底获得了什么；
- 对话中存在多个分支，部分问题讨论到一半后被遗忘；
- 助手提出了很多建议，但用户未必已经接受，容易把“建议”误认为“最终决定”；
- 项目目标、需求、技术方案和下一步散落在不同消息中；
- 用户下次继续对话时，需要重新阅读大量历史消息；
- 普通摘要通常只复述内容，无法区分共识、决定、分歧、困惑、未解决问题和行动项。

Chat Graph 已经负责把线性对话组织为节点和分支，因此“对话总结”应进一步把一次对话转化为可复用的项目成果、学习成果和后续行动，并能够重新关联到图中的原始消息。

---

## 2. 产品目标

### 2.1 核心目标

用户点击“总结”后，可以自行勾选希望整理的内容，系统基于指定范围生成结构化总结，并支持保存、复制、导出和写回对话图。

### 2.2 用户完成总结后应能回答

- 这一轮主要讨论了什么？
- 我的真实目标是什么？
- 我获得了哪些新认识？
- 哪些内容已经形成共识或决定？
- 我与助手之间有哪些分歧？
- 哪些问题仍未解决或被遗漏？
- 我有哪些技术细节仍未搞清楚？
- 当前产品方案、技术栈、流程和范围是什么？
- 下一步最应该做什么？
- 下次继续讨论时，需要携带哪些上下文？

### 2.3 产品价值

1. **把聊天转化为成果**：从“看完一段聊天”变为“得到可执行结论”。
2. **降低分支遗忘**：主动发现未跟进问题和可继续讨论的分支。
3. **提高结论可信度**：区分助手建议、用户决定、双方共识和暂定方案。
4. **支持项目延续**：生成可以直接用于下一轮对话的上下文包。
5. **增强对话图价值**：总结不只是文本，还能成为图中的节点并链接回证据消息。

---

## 3. 非目标

V0.1 不负责：

- 自动替用户决定采用哪套方案；
- 自动修改原始对话内容；
- 对事实进行外部联网核验；
- 自动生成完整 PRD、代码、测试用例等后续交付物；
- 在没有用户确认的情况下，把助手建议标记为最终决定；
- 自动总结用户全部历史会话；
- 自动合并多个独立项目；
- 复杂的多人协作、审批和云端共享。

---

## 4. 目标用户与使用场景

### 4.1 目标用户

- 经常与 GPT 进行长对话的个人用户；
- 使用 GPT 讨论产品、开发、研究或学习问题的用户；
- 需要在多个分支之间切换并持续推进项目的用户；
- 希望将聊天结论沉淀到笔记、PRD、任务系统或下一次会话中的用户。

### 4.2 核心场景

#### 场景 A：项目讨论结束后复盘

用户讨论了需求、方案、技术栈和版本安排，希望快速确认当前项目结论与下一步。

#### 场景 B：技术答疑后整理认知

用户连续追问多个技术概念，希望知道哪些问题已经理解、哪些仍不清楚，以及自己的理解发生了什么变化。

#### 场景 C：多方案决策

用户比较了多个实现方式，希望回顾候选方案、分歧、取舍、否决原因和最终选择。

#### 场景 D：分支恢复

用户在讨论一个子问题时切换到了其他分支，希望系统发现没有继续的问题，并创建后续讨论节点。

#### 场景 E：跨会话继续工作

用户准备开启新对话，希望生成一份自包含的上下文包，避免重新解释已知信息。

## 5. 产品范围

### 5.1 V0.1 必须支持

- 从当前对话页或 Chat Graph 详情页进入总结功能；
- 选择总结范围；
- 使用预设模板或手动勾选总结内容；
- 一次生成多个已选总结模块；
- 展示生成状态、成功结果、部分失败和错误信息；
- 查看每个总结模块及其原始消息依据；
- 跳转到对应消息或图节点；
- 编辑总结标题和正文；
- 复制完整总结或单个模块；
- 导出 Markdown；
- 将总结保存为图节点；
- 生成“下次继续对话上下文包”；
- 对长对话给出明确处理状态，不允许静默遗漏内容。

### 5.2 后续版本候选

- 框选任意多个节点作为总结范围；
- 定时或自动总结；
- 多次总结之间的版本差异；
- 多对话合并总结；
- 总结质量反馈与个性化偏好；
- 将行动项同步到外部任务管理工具；
- 自动生成 PRD、Roadmap、Checklist 等二次产出；
- 团队共享、评论与审批。

## 6. 信息架构

总结功能包含两个主要页面状态：

1. **总结配置页**：选择范围、预设和具体总结内容；
2. **总结结果页**：查看、核对、编辑、复制、导出和保存结果。

推荐入口：

- 对话悬浮窗中的“总结”按钮；
- Chat Graph 详情页顶部工具栏；
- 当前节点的更多菜单；
- 分支结束提示中的“总结当前分支”。

---

## 7. 总结范围

### 7.1 当前分支

- 默认选项；
- 从当前分支的起点或根节点，到当前节点为止；
- 适合复盘当前讨论路径；
- 不包含其他未激活分支。

### 7.2 整个当前对话

- 汇总当前会话内所有已捕获节点；
- 适合项目级复盘；
- 对存在互相冲突的分支，应在结果中保留分支差异，不得直接混成唯一结论。

### 7.3 当前节点及其上下文

- 只总结当前节点、父节点及必要祖先信息；
- 适合快速理解某个局部问题；
- 可以从节点菜单直接触发。

### 7.4 范围提示

生成前必须显示：

- 当前选中的范围类型；
- 将包含的大致消息数或节点数；
- 是否包含其他分支；
- 对话过长时将采用的处理方式或限制提示。

---

## 8. 总结内容选择

### 8.1 展示原则

为了避免首次使用时面对过多选项，界面采用：

- **常用内容**：默认展示；
- **更多内容**：按类别折叠；
- **预设模板**：一键勾选一组内容；
- 用户始终可以在预设基础上继续增删选项。

### 8.2 常用内容

V0.1 默认展示以下十项：

1. 我们讨论了什么；
2. 我的目标是什么；
3. 我获得了什么关键收获；
4. 最终达成了什么共识；
5. 我最终做出了什么决定；
6. 还有哪些问题没有解决；
7. 哪些讨论分支被遗漏；
8. 我有哪些地方没搞清楚；
9. 下一步应该做什么；
10. 下次继续对话的上下文包。

### 8.3 更多内容分组

#### 决策复盘

- 考虑过哪些方案；
- 中间有哪些分歧；
- 最终选择时做了哪些取舍；
- 哪些方案被否决、暂缓或排除在当前版本外；
- 当前结论依赖哪些假设和约束；
- 哪些信息仍需验证。

#### 学习与理解

- 哪些技术细节已经解释清楚；
- 我的认知发生了什么变化；
- 本轮出现了哪些重要术语；
- 我还缺少哪些前置知识。

#### 项目落地

- 产品要解决什么问题；
- 当前确认了哪些需求和范围；
- 当前方案和系统架构；
- 当前技术栈；
- 完整业务流程和技术流程；
- 数据、接口、Tools 和 Skills；
- 风险和依赖；
- 当前进度与版本计划；
- 验收标准；
- 需要向客户或其他人确认的问题；
- 本轮产生的产出物。

#### 对话建图

- 当前分支对主问题的贡献；
- 哪些问题适合拆成新分支。

### 8.4 预设模板

#### 通用复盘

包含主题、目标、关键收获、共识、决定、未解决问题和下一步。

#### 技术项目

包含产品定义、需求范围、架构、技术栈、流程、接口、风险、进度、验收和下一步。

#### 学习答疑

包含关键收获、困惑、已澄清技术细节、认知变化、术语和知识缺口。

#### 决策复盘

包含候选方案、分歧、取舍、决定、否决或暂缓方案、假设和待验证信息。

#### 继续对话

包含目标、已做决定、重要约束、未解决问题、遗漏分支、下一步和上下文包。

## 9. 核心用户流程

### 9.1 标准流程

1. 用户点击“总结”；
2. 系统默认选择“当前分支”；
3. 用户选择一个预设，或手动勾选总结内容；
4. 系统显示预计包含的消息或节点范围；
5. 用户点击“生成总结”；
6. 系统展示生成进度；
7. 结果按用户勾选的模块分区显示；
8. 用户展开某条结果，查看对应原始消息；
9. 用户可修改标题或正文；
10. 用户选择复制、导出 Markdown、保存为图节点或生成继续对话文本。

### 9.2 从节点触发

1. 用户在某个节点的更多菜单中点击“总结”；
2. 系统默认选择“当前节点及其上下文”；
3. 用户可切换为“当前分支”；
4. 完成后可把总结节点连接到当前节点。

### 9.3 重新生成

- 用户可以重新生成全部结果；
- 用户可以仅重新生成一个模块；
- 重新生成前保留用户手动编辑的版本，避免直接覆盖；
- 用户明确选择替换后，才更新已保存内容。

## 10. 功能需求

### 10.1 总结入口

- 所有入口使用统一的总结配置界面；
- 入口应能自动带入当前对话、当前节点和当前分支信息；
- 没有捕获到有效对话时，按钮不可用并说明原因。

### 10.2 选项选择

- 支持预设一键选择；
- 支持单项勾选和取消；
- 支持分组全选与清空；
- 至少选择一项后才能生成；
- 显示当前已选项数量；
- 用户上一次使用的范围和选项可在本地记忆，但不能覆盖当前入口带入的节点范围。

### 10.3 生成状态

至少包含：

- 等待生成；
- 正在整理对话；
- 正在生成总结；
- 已完成；
- 部分完成；
- 已取消；
- 生成失败。

生成期间用户可以关闭面板，但再次打开时应能看到当前状态。若插件当前架构无法保持任务，应明确提示关闭面板会中断。

### 10.4 结果展示

- 只展示用户勾选的模块；
- 模块顺序与配置页保持一致；
- 每个模块可折叠；
- 每个模块显示一句概览和详细条目；
- 没有相关内容时显示“本轮未发现相关内容”，不能编造内容填充；
- 同一结论在多个模块中出现时，应根据模块目的重新表述，避免大段重复；
- 对“已确定、暂定、建议、未解决、已否决、已延后”等状态提供明显区分；
- 对系统推断内容提供提示，不得与用户明确决定混为一谈。

### 10.5 原始消息依据

- 每条关键结论支持查看相关原始消息；
- 点击依据后，跳转到对话页对应消息或图中的对应节点；
- 若来源来自多个分支，应显示分支位置；
- 系统不得展示不存在或无法定位的消息引用；
- 对无法提供明确依据的推断，必须标记为推断。

### 10.6 编辑

- 用户可以修改总结标题；
- 用户可以修改模块正文；
- 用户可以删除单条结果；
- 用户可以恢复至最近一次模型生成版本；
- 编辑后的内容应标记为“已编辑”，避免与原始生成结果混淆。

### 10.7 复制与导出

- 支持复制完整总结；
- 支持复制单个模块；
- 支持导出为 Markdown 文件；
- 导出内容应包含标题、总结范围、生成时间和所选模块；
- 不强制在导出文件中包含全部原始消息；
- 用户可以选择是否保留消息引用。

### 10.8 保存为图节点

- 用户可将总结保存为一个独立节点；
- 默认连接到当前节点或当前分支末端；
- 节点标题默认采用总结标题，用户可修改；
- 节点应保留总结范围和来源关系；
- 对同一范围重复保存时，应提示“创建新版本”或“更新原总结”，避免无提示地产生重复节点；
- 总结节点与普通问题节点在视觉上应有可辨识差异。

### 10.9 新分支候选

当用户选择“适合拆出的新分支”时：

- 展示建议的分支标题和继续讨论的第一个问题；
- 用户可以选择其中一项创建新节点；
- 系统不得自动创建分支；
- 已经解决的问题不应被重复建议为新分支。

### 10.10 下次继续对话

- 提供一份可直接复制到新会话中的自包含上下文；
- 内容应优先保留目标、决定、约束、当前方案、未解决问题和下一步；
- 不重复整段聊天；
- 已知信息应明确写出，减少新会话再次询问；
- 支持一键复制和保存为图节点。

### 10.11 长对话处理

- 生成前检测对话长度；
- 对话超出模型可处理范围时，不得静默截断；
- 应采用分段整理、先压缩再总结，或明确提示用户缩小范围；
- 结果页应提示是否经过分段处理；
- 分段后仍需保持不同分支、时间顺序和结论状态的一致性；
- 若部分内容处理失败，应标记缺失范围并允许重试。

### 10.12 错误处理

至少覆盖：

- 未配置模型或 API；
- API 鉴权失败；
- 请求超时；
- 模型返回异常；
- 对话内容为空；
- 节点关系缺失；
- 本地保存失败；
- 导出失败；
- 用户主动取消。

每类错误应提供清晰原因和可执行的恢复操作，不能只显示“生成失败”。

## 11. 交互与界面要求

### 11.1 总结配置页

推荐结构：

1. 标题与关闭按钮；
2. 总结范围；
3. 预设模板；
4. 常用选项；
5. 折叠的更多选项；
6. 已选数量与“清空”；
7. 生成按钮。

交互要求：

- 默认使用“当前分支 + 通用复盘”；
- 切换预设时，先更新勾选状态，不立即生成；
- 用户手动调整预设后，显示“自定义”；
- 关闭面板前，如果存在未保存配置或结果，给出提示。

### 11.2 结果页

推荐结构：

1. 总结标题；
2. 范围、时间和状态；
3. 顶部操作区；
4. 按模块排列的总结卡片；
5. 原始消息依据抽屉；
6. 保存到图或继续对话操作区。

### 11.3 视觉状态

应明确区分：

- 已确认；
- 用户决定；
- 双方共识；
- 助手建议；
- 暂定；
- 未解决；
- 已延后；
- 已否决；
- 系统推断；
- 用户手动编辑。

不要求 V0.1 使用复杂颜色体系，但必须通过标签、图标或文字避免混淆。

---

## 12. 与 Chat Graph 的联动

### 12.1 节点关系

- 总结节点可以连接当前节点、分支起点或对话根节点；
- 当前分支总结默认连接到分支末端；
- 全局总结默认连接到项目根节点；
- 局部节点总结默认连接到被总结节点。

### 12.2 节点内容

总结节点至少需要让用户看到：

- 总结标题；
- 总结范围；
- 已选择的总结模块；
- 模块内容；
- 来源节点跳转；
- 生成时间和是否被用户编辑。

### 12.3 更新逻辑

- 对话新增消息后，旧总结不自动改变；
- 旧总结显示“该范围后续已有新消息”提示；
- 用户可以基于新增消息创建新版本；
- 更新旧总结前必须保留历史版本或获得用户明确确认。

---

## 13. 数据与隐私要求

- 仅发送用户所选范围内的消息；
- 生成前明确显示范围；
- 遵循插件已有的模型和 API 配置；
- 不在日志中记录完整对话正文；
- 本地保存的总结应遵循现有项目存储策略；
- 用户删除总结节点后，应同时删除对应本地总结记录；
- 复制和导出由用户主动触发；
- 若未来支持云同步，需要单独增加授权和隐私说明。

---

## 14. 非功能要求

### 14.1 可用性

- 用户无需理解 Prompt、上下文窗口或模型参数即可使用；
- 默认配置应适合大多数普通对话；
- 所有失败状态都应可重试或缩小范围后重试；
- 结果为空时应提供原因，而不是显示空白页。

### 14.2 一致性

- 同一范围、同一选项的多次结果允许措辞不同，但关键决定和状态不应互相矛盾；
- 当前分支与全局总结对同一结论的状态应保持一致；
- 后续消息推翻前述结论时，最新总结应体现变化。

### 14.3 可追溯性

- 关键结论应尽量关联到原始消息；
- 跳转后应定位到具体消息，而不是只打开对话首页；
- 无法确认来源时，应显示“推断”或“依据不足”。

### 14.4 性能体验

- 点击总结后应立即进入配置页；
- 点击生成后应立即显示进度反馈；
- 生成时间较长时，用户仍可查看已完成模块；
- 单个模块失败不应导致全部结果丢失。

## 15. 风险与应对

### 15.1 把助手建议误写为用户决定

应对：在结果展示中强制区分建议、暂定、共识和用户决定，并提供原始消息依据。

### 15.2 选项过多导致操作负担

应对：默认只展示常用项，其他选项分组折叠，并提供预设模板。

### 15.3 长对话遗漏早期信息

应对：增加长度检测、分段处理提示和缺失范围说明，不允许静默截断。

### 15.4 多分支结论冲突

应对：保留分支来源和状态差异，不强行合并为单一最终结论。

### 15.5 总结内容重复

应对：每个模块回答不同问题，结果页检测大段重复，并允许用户仅重试单个模块。

### 15.6 用户过度依赖模型结论

应对：提供证据跳转、推断标识和编辑能力，强调总结是辅助整理而不是替代用户确认。

### 15.7 API 成本和响应时间过高

应对：只处理用户所选范围和模块；支持缩小范围；长对话采用分段策略；避免为每个模块分别发起完整对话请求。

## 16. 验收标准

### 16.1 基础流程

- 用户能从对话页和图详情页打开总结功能；
- 默认范围为当前分支；
- 用户可以使用预设并继续手动调整选项；
- 未选择任何内容时不能生成；
- 生成结果只包含已勾选模块；
- 用户可重新生成全部结果或单个模块。

### 16.2 结果可信度

- 助手单方面建议不会无提示地显示为用户决定；
- 暂定、未解决、已否决和已延后的内容有明确状态；
- 后续消息修正前述结论时，结果采用最新结论；
- 没有相关内容的模块显示“未发现”，而不是编造内容；
- 关键结论可以查看原始消息依据或明确标记为推断。

### 16.3 图联动

- 总结可以保存为图节点；
- 总结节点能跳转到来源消息或节点；
- 重复保存同一范围时有更新或创建新版本提示；
- 对话新增内容后，旧总结能提示存在后续消息。

### 16.4 导出与继续工作

- 可以复制完整总结和单个模块；
- 可以导出有效的 Markdown 文件；
- 可以生成并复制下次继续对话的上下文包；
- 用户编辑后的内容可以保存和导出。

### 16.5 异常场景

- 空对话、API 未配置、鉴权失败、超时、部分模块失败和保存失败均有明确提示；
- 长对话不会被静默截断；
- 单个模块失败时，已完成模块仍然可查看和保存。

## 17. V0.1 发布边界

V0.1 可以发布的最低条件：

1. 当前分支总结流程完整可用；
2. 十个常用总结项可选择并生成；
3. 至少提供“通用复盘、技术项目、学习答疑、决策复盘、继续对话”五个预设；
4. 结果可以查看原始消息依据；
5. 支持复制、Markdown 导出和保存为图节点；
6. 支持重新生成单个模块；
7. 长对话和常见 API 错误有明确处理；
8. 通过本 PRD 中的核心验收用例。
