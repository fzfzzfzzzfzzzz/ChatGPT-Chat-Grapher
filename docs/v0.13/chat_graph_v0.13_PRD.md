# Chat Graph v0.13 PRD — 引用感知节点

> 版本：v0.13  
> 产品形态：ChatGPT 网页版浏览器扩展  
> 本版本核心：让问题图在保持轻量的前提下，识别并展示用户问题引用的附件、图片和 Assistant 回答。

## 1. 背景

当前问题节点只展示问题、摘要与状态。用户的问题如果依赖附件、图片或先前的 GPT 回答，进入图后会失去这些上下文，用户只能凭问题文字猜测引用来源。

v0.13 不把 Chat Graph 扩展为完整聊天数据库，也不把引用内容自动拆成新的知识节点。引用作为问题节点的附属信息存在，用于回答两个问题：

1. 这个问题引用了什么？
2. 如何回到引用的原始位置？

## 2. 产品目标

- 自动识别用户消息中的文件、图片和 Assistant 回答引用。
- 在问题节点和详情中显示引用类型与数量。
- 图片在本地保存受限尺寸的缩略图，原图继续由 ChatGPT 保存。
- Assistant 引用只保存短摘录和消息定位，不保存完整回答。
- 点击引用可在当前 ChatGPT 页面定位并高亮对应消息。
- 刷新浏览器后，引用元数据和已保存的缩略图仍可使用。
- 引用识别失败时不影响问题捕获、父节点推荐或图导航。

## 3. Scope Lock

### 3.1 本版本实现

- `file`：文件名、MIME、大小（页面可获取时）与用户消息定位。
- `image`：名称或替代文本、受限尺寸的本地缩略图与用户消息定位。
- `assistant_quote`：最多 500 字的引用摘录与 Assistant 消息定位。
- 图节点引用计数、详情引用列表、浮窗当前问题引用摘要。
- 用户消息和 Assistant 消息两种角色的原文定位。
- 引用数据的本地持久化、备份校验与导入恢复。

### 3.2 本版本不实现

- 保存附件正文或原始图片。
- 保存完整 Assistant Answer。
- 把附件、图片或回答自动创建为独立图节点。
- 新增 Resource / Answer / Citation 边类型。
- 跨会话自动打开原会话。
- OCR、附件全文索引、图片内容理解。
- 默认把引用内容发送给第三方 AI 服务。

## 4. 交互设计

### 4.1 详情问题视角

问题节点在问题文字下方显示紧凑徽标：

```text
如何根据这份设计稿调整布局？
📎 1   🖼 2   💬 1
```

徽标只表达引用存在与数量，不在画布上展开完整内容。点击或右键“查看总结与详情”进入引用列表。

### 4.2 节点详情

引用列表按捕获顺序展示：

```text
附件  product-requirements.pdf
图片  [缩略图] architecture.png
回答  “建议将缓存拆分为两层……”
```

每条引用提供“定位原文”。图片缩略图可点击预览；无法定位时仍保留本地引用信息。

### 4.3 浮窗

- Current 卡片显示引用计数。
- 图视角圆点保持紧凑，悬浮提示附带引用计数。
- 不在浮窗图画布直接铺开图片或长回答。

## 5. 数据设计

引用以内联数组附着在 `CapturedQuestion`、`QuestionCandidate` 和 `QuestionNode`：

```ts
type QuestionReference =
  | FileQuestionReference
  | ImageQuestionReference
  | AssistantQuoteQuestionReference;
```

共同约束：

- 每个问题最多 20 条引用。
- 引用 ID 在单条问题内唯一。
- Assistant 摘录最多 500 字。
- 缩略图最大边长 320px，单张目标大小不超过 200KB。
- `thumbnailDataUrl` 仅允许 `image/png`、`image/jpeg` 或 `image/webp`。
- 老数据缺少 `references` 时等价于空数组。

MVP 将受限缩略图作为 Data URL 与引用元数据一并存储，避免临时 ChatGPT 图片 URL 过期。后续若容量评估显示需要，再迁移到独立 Blob 表。

## 6. 捕获与定位

### 6.1 捕获

- 捕获发送后的用户消息 DOM，不依赖 Composer 中的未提交状态。
- 优先使用稳定的 `data-testid`、`data-message-id`、`data-turn-id`、`aria-label` 和语义元素。
- DOM 选择器集中在 ChatGPT Adapter 中，UI 不直接解析页面 DOM。
- 图片已加载且 Canvas 可读取时生成本地缩略图；失败时保留名称/替代文本并降级显示。
- 原生引用无法提供 Assistant ID 时，保存 Assistant 角色、顺序和文本指纹作为回退定位。

### 6.2 定位

定位优先级：

1. `messageId`
2. `turnId`
3. 消息顺序与文本指纹
4. 全文指纹扫描

定位支持 ChatGPT 虚拟化历史扫描。附件和图片定位整个用户 Turn；回答引用定位 Assistant Turn。

## 7. 隐私与安全

- 所有引用信息默认仅保存在扩展本地 IndexedDB。
- 不下载或复制附件正文。
- 不保存完整 GPT 回答。
- 不把缩略图、文件名或回答摘录默认发送给父节点推荐模型。
- 备份包含引用元数据与本地缩略图，因此导出提示必须说明可能包含敏感信息。
- 严格限制引用数量、摘录长度、Data URL MIME 与大小，导入时重新校验。

## 8. 兼容与降级

- 未识别引用：继续捕获普通问题。
- 图片无法生成缩略图：显示图片占位符与名称。
- 引用来源无法定位：显示“原消息不可用”，保留本地内容。
- ChatGPT DOM 变化：引用提取可失效，但不得导致 Content Script 崩溃。
- 旧节点、旧 IndexedDB 和旧备份仍可读取。

## 9. 验收标准

1. 带附件、图片或 Assistant 引用的问题进入图后显示正确计数。
2. 节点详情能展示文件名、图片缩略图和回答摘录。
3. 刷新后引用仍可见。
4. 点击引用能够定位并高亮对应的用户或 Assistant 消息。
5. 原消息丢失时，本地元数据仍可见。
6. 引用提取失败不影响问题节点创建。
7. 备份导出、导入后引用完整且通过安全校验。
8. 普通问题捕获、图交互、父节点推荐与现有备份均无回归。
